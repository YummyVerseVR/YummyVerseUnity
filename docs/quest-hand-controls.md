# Quest 3 ハンド操作と咀嚼音（2026-10-07）

ブランチ: feat/quest-hand-controls

## 操作
- 設定画面は従来通りコントローラーを使用する。A + Xで設定を開き、食品位置・接続設定などを済ませる。
- Questのハンドトラッキングを有効にし、コントローラーを置いて手に切り替える。
- 開始待ちでは空中の「スタート」を押す。説明中に進行待ちがあるときは「次へ」を押す。
- 進行ボタンは顔の前方65cm、25cm下に表示される。表示時に位置を決め、常時頭には追従させない。
- 初回・2回目の選択ボタンは既存UIを使用する。
- 食品メニューは1ページ8件。「前へ」「次へ」で切り替える。最初と最後のページでは対応するボタンは無効。食品カードを手のレイ＋ピンチで選択するか、届く位置にあるUIを指で押す。
- 進行ボタンと食品CanvasはInteraction SDKのPointableCanvas、RayInteractable、PokeInteractableを使用する。シーン既存のOVRInteractionComprehensiveが手のInteractorを提供する。
- Metaのプロジェクト設定はControllersAndHands。コントローラー入力も残している。

## 咀嚼音
S3とのUSB CDCプロトコル（HELLO/READY、MOUTHのOPEN/CLOSED）は変更しない。USBスピーカーとしてUnityから音を出す。
- CLOSED: 前回の停止位置から再生。
- OPEN: 即座に一時停止。
- 1回のCLOSEDから最大0.8秒で自動停止。CLOSEDが連続しても停止期限を延長しない。
- 音源末尾に到達したら先頭へループ。停止中は再生位置を進めない。
- 食品を切り替えた場合は停止し、新しい音源の先頭から始める。
- UnityのDSP時刻で停止期限を予約する。メインスレッドの更新が遅れても0.8秒を超えて鳴らし続けない。
Quest/PCの同時出力はMeta Horizon Link側の「コンピューターでVR音声を聞く」を使用する。PCの既定出力をS3に設定する。

## 検証
EditModeテストで途中再開、0.8秒上限、重複CLOSED、末尾ループ、食品変更時のリセット、17件のページ遷移、空のメニューを確認する。
Quest実機での指押し・ピンチの操作感と、実センサーに連動した両出力の音は装着して確認が必要。
